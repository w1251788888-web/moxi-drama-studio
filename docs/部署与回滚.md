# 部署与回滚

> 适用版本：墨戏生花 v2（DSH `0.2.1-rc.5`）
> 原则：专用 profile 隔离、项目数据与代码分离、每步可回滚。

---

## 1. 前置条件

| 项 | 要求 | 检查 |
|---|---|---|
| DSH | `0.2.1-rc.5` | `dsh --version` |
| Node | `^22.19.0 \|\| >=24` | `node --version` |
| Python | 3.11+（仅迁移/导出脚本需要） | `python3 --version` |
| 磁盘 | ≥ 500MB（bundle + node_modules） | `df -h ~` |

---

## 2. 安装

```bash
cd <仓库根>
bash dsh/profile/install.sh
```

脚本做四件事：
1. 若 `~/.dsh/profiles/moxi` 不存在 → 从 shipped `web` 模板创建；
2. `dsh plugin --profile moxi add` 三个本地 bundle（pnpm link，自动写入 `dsh.profile.bundles`）；
3. 技能安装是**可选**的（默认不动 `~/.dsh/skills`）：需要时加 `MOXI_INSTALL_SKILL=1`，
   它会先把现有技能（含符号链接指向的真实目录）备份，再装入 v2；
4. 校验三个 bundle 都已挂载、技能已就位。

**不会动 `desktop` profile**，用户现有界面不受影响。

> ⚠ 技能安装的两种情况：
> - `~/.dsh/skills/moxi-drama-creation` 是**普通目录** → 备份成 `*.bak.<时间戳>` 后替换；
> - 它是**符号链接**（例如指向 WorkBuddy 的 skills 目录）→ 会先 `cp -RL` 把链接目标的真实内容备份成目录，
>   再替换链接。若不想改动链接关系，**保持默认（不装技能）**，直接让 Agent 读仓库里的 `skills/` 即可。

---

## 3. 启动

```bash
dsh --profile moxi
```

- 终端会打印 `http://127.0.0.1:<port>/?token=...`，首次访问用它登录（之后浏览器带 cookie）。
- 侧栏出现「墨戏画布」与「墨戏后台」两个入口。
- 项目数据默认在 `~/Documents/Moxi/projects`；可用 `MOXI_PROJECTS_ROOT=/path` 覆盖（需重启实例）。

**开发模式**（不打开浏览器、指定端口）：

```bash
dsh --profile moxi --no-open --port 59911
# 改客户端：node scripts/build-client.mjs && 刷新页面
# 改 Host：重启实例
```

---

## 4. 升级

```bash
cd <仓库根>
git pull
node scripts/build-client.mjs      # 客户端源码变了才需要
bash dsh/profile/install.sh        # 重新 link（pnpm 会同步）
# 重启 dsh --profile moxi
```

数据兼容：`project.json` / `canvas.json` 都有 `schemaVersion`；升级脚本在 `scripts/migrate/`。

## 5. 回滚

### 5.1 回滚到上一个代码版本

```bash
cd <仓库根>
git log --oneline -5               # 找目标 commit
git checkout <commit> -- dsh/ scripts/ skills/ rules/
node scripts/build-client.mjs
bash dsh/profile/install.sh
```

### 5.2 回滚整个产物（停用 v2）

v2 与 v1 不共享运行时，停用 v2 不会影响桌面 profile 与项目数据：

```bash
bash dsh/profile/install.sh --uninstall
```

v1（FastAPI + Vue3 单体）只作为历史参考保留在开发记录里，不再参与运行；
v2 的架构动机见 `docs/adr/001-目标架构.md`。

### 5.3 回滚项目数据

- 删除类操作是**软删**：项目移到 `<projectsRoot>/.trash/<projectId>.<ts>/`，直接搬回即可。
- 写事务有 WAL：崩溃后打开项目会自动 `recover`（回滚或前滚），逻辑见 `docs/设计/数据契约-v1.md` §9。
- 单节点历史：`versions/<nodeId>/` + `history/events.jsonl`。

## 6. 故障排查

| 现象 | 原因 / 处置 |
|---|---|
| 侧栏没有「墨戏画布」 | bundle 未挂载：`dsh --profile moxi --dump-config \| grep moxi` 检查；重跑 `install.sh` |
| 面板空白 + 控制台 `slot entry crashed` | 客户端产物损坏：`node scripts/build-client.mjs` 后刷新 |
| `/api/moxi/*` 返回 `not found` | Host 半未加载：看启动日志 `moxi-core ... failed to import`；确认 bundle 语法 `node --check` |
| 面板显示「项目列表读取失败」 | moxi-core 的 ProjectsRoot 不可写：检查目录权限或 `MOXI_PROJECTS_ROOT` |
| 导出 docx 变成 md | 本机 python 缺 `python-docx`：`pip install python-docx`（或接受降级，结果里会写明原因） |
| 规则页 0 文件 | `rules/v2/pipeline.json` 不存在：确认仓库完整 |
| 端口被占用 | 换 `--port`，或 `lsof -i :59911` 找占用进程 |

日志：`dsh --profile moxi --no-open --port 59911 > /tmp/moxi-web.log 2>&1`。
