## 0. 结论先行

1. **DSH Client 插件能做什么，已经实测确认**：React 组件 + slot 注册 + 宿主 HTTP 路由，足够承载「无限画布工作台」与「管理后台」两个界面。
2. **客户端 ↔ Host 的唯一可靠通道**：Host 用 `ctx.connection.fetch.register({path:'/api/<ns>/...'})` 注册路由；Client 用同源 `fetch('/api/<ns>/...')` 调用。**没有通用文件读写服务**，所以项目数据必须经 Host 路由中转。
3. **界面挂载点**：`sidebar.panellist`（侧栏图标 list slot）+ `main`（keyed slot，key=侧栏 id）。**不替换 app root**，符合 `02 约束` 第 2 条。
4. **不需要构建工具也能交付**：客户端产物是纯 JS 文件 `window.__ModuleLoader__.load({id, factory(require){...}})`，`require('react')` 由宿主模块表提供。复杂 UI 建议用 esbuild 打包成同格式，属工程便利，不是硬约束。
5. **安装路径两条**：`plugin_manager install_bundle`（需审批，本会话审批被禁用 → 会被拒）或 `dsh plugin --profile <name> add <本地目录>`（pnpm 转发，bash 可执行）。**S1.3 实测确认走哪条**。

## 1. 集成面实测（证据）

### 1.1 侧栏入口：`sidebar.panellist`

| 项 | 实测值 |
|---|---|
| 类型 | `list` slot，scope=root |
| 注册参数 | `id`（必填，自有 id）、`order`（数字）、`label`（字符串或 thunk，按 locale 重读） |
| 组件收到的 owner props | `{ size: number; active: boolean }`（图标尺寸与是否选中） |
| 现有占用 | `plugins`(order 0)、`schedules`(10)、`dsh-context`(20) |
| 语义 | **每个 list id 对应一个 main 面板 key**；侧栏负责按钮，label 由 slot 元数据解析 |

### 1.2 主面板：`main`

| 项 | 实测值 |
|---|---|
| 类型 | `keyed` slot，scope=root |
| 注册参数 | `key`（必填；"your cell key，owner 按此 key 派发"） |
| 现有 key | `conversation`、`plugins`、`schedules`、`dsh-context` |
| 标准 props | `useRemoteAccess` / `useResource` / `useContextMenu` / `useWorkspaces` / `usePanelInfo` / `useSessions` / `useSessionStatus` / `useSessionRetainInfo` / `useSessionAccess` / `useWorkspaceAccess` |
| 注意 | `conversation` 是保留 key，承载对话；其它 key 不绑定 session |

> **画布与后台的挂载方案**：`sidebar.panellist` 注册 `moxi-canvas`(order 30) 与 `moxi-admin`(order 40)；
> `main` 注册同名 key 渲染对应面板。切换由 `ctx.layout.selectPanel(id)`（client Service `layout`）完成。

### 1.3 Host → Client 数据通道：`connection.fetch`

来自 Host Service 契约（`cordis_inspect_query host/Service connection`）：

```ts
interface ConnectionFetchRoute {
  readonly path: string;
  readonly methods: readonly ('GET' | 'HEAD' | 'POST')[];   // 只允许这三种
  readonly requestBody: 'buffered' | 'streaming';
  readonly fetch: (request: Request) => Promise<Response>;
}
interface HostConnectionFetch { register(route: ConnectionFetchRoute): () => Promise<void>; }
```

Host 插件里注册（照抄已装插件 `dsh-context` 的写法）：

```js
ctx.inject(['connection'], (ctx) => {
  const conn = ctx.get('connection');
  ctx.effect(() => conn.fetch.register({
    path: '/api/moxi/canvas/get',
    methods: ['POST'],
    requestBody: 'buffered',
    fetch: async (request) => Response.json({ ok: true, value: {...} }),
  }));
});
```

Client 端（同源相对路径，`dsh-context` 同款）：

```js
const res = await fetch('/api/moxi/canvas/get', {
  method: 'POST', headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ projectId }),
});
```

> **限制**：没有 `PUT/PATCH/DELETE`，写操作统一用 `POST /api/moxi/<action>` 语义化路由（如 `/api/moxi/node/update`）。

### 1.4 现有插件对照（`dsh-context`，已装 0.82.0）

| 项 | 事实 |
|---|---|
| host 半 | `lib/index.js`，`ctx.inject(['connection'], ...)` 注册 9 个 `/api/dsh-context/*` 路由 |
| client 半 | `lib/client.js`，`window.__ModuleLoader__.load({id:'dsh-context', factory})`，依赖 `react` 与 `@deepseek-ai/dsh-client-ui-primitives` |
| 数据流 | client `fetch('api/dsh-context/snapshot')` → host 读 session 事件算好 → JSON 返回 |
| 显示 | 面板 + 设置段 |
| **重要约束** | `references/practices.md` 明确："**不要 require `@deepseek-ai/dsh-client-ui-primitives`** 或其他 Harness Client 包"——dsh-context 这么做了，但官方指导是自写控件 + 用 `--dsw-alias-*` 主题 token |

### 1.5 Client 可用 Service（实测目录）

`layout` / `locale` / `sessions` / `slots` / `theme` / `timer` / `uiWorkspace` / `workspaces`
—— 与画布相关的：`layout.selectPanel(panelId)`、`locale.register`、`theme` token、`uiWorkspace.pickDirectory/listDirectory`。

### 1.6 客户端产物的运行形态（实测）

```js
window.__ModuleLoader__.load({
  id: '<package name>',
  factory(require) {
    const React = require('react');
    const h = React.createElement;
    return { inject: ['slots'], apply(ctx) { ctx.slots.inject('main', () => ctx.slots.register({ name:'main', key:'moxi-canvas' }, CanvasPanel)); } };
  },
});
```

- `id` **必须等于 package name**（模块表按此解析）。
- factory 内不得有副作用；资源注册放 `apply`，用 `ctx.effect`/`ctx.on` 返回清理函数。
- 失败模式：组件抛错会**整块 slot 变空白**（console: `slot entry crashed in '<slot>'`）。

## 3. 还没验的（S1.3 必须补）

1. **安装路径**：`dsh plugin --profile moxi add <dir>` 能否把本地 bundle 装进**独立 moxi profile**（不污染 desktop）。
2. **启动第二个实例**：`dsh --profile moxi web --port <port>` 是否能起、能否用浏览器访问。
3. **最小面板冒烟**：装一个注册 `moxi-canvas` key 的空面板，确认侧栏图标 + 主面板真的出现。
4. **写操作通道**：`POST /api/moxi/*` 在本机同源下是否需要额外鉴权（`connection` 是 trusted/authenticated 的，需实测 401/403 情况）。
5. **数据持久化**：Host 路由读写的文件路径 = 哪个工作区（会话工作区 / profile 目录 / 用户选的目录）。

## 5. spike 实测结果（2026-11-06 01:37，已通过）

### 5.1 做了什么

1. 新建**专用 profile `moxi`**（从 shipped `web` 模板复制，不碰 desktop）：
   `dsh --profile moxi --from-default-profile web --dump-config`
2. 写最小 bundle `dsh/bundles/moxi-canvas/`（package.json + cordis.patch.yml + index.js + client.js + locale + icon）。
3. 安装：`dsh plugin --profile moxi add <仓库根>/dsh/bundles/moxi-canvas`
   → pnpm 生成 `link:` 依赖，**并自动把 `moxi-canvas-bundle` 写进 `~/.dsh/profiles/moxi/package.json` 的 `dsh.profile.bundles`**。
4. 校验：`dsh --profile moxi --dump-config | grep moxi` → 出现
   ```
   # == moxi-canvas-bundle
   - id: moxi-canvas
     name: moxi-canvas-bundle
   ```
   退出码 0，配置 1234 行。
5. 启动：`dsh --profile moxi --no-open --port 59911`
   → `dsh web: http://127.0.0.1:59911/?token=…`（PID 82423，CWD = 启动时目录）。
6. 浏览器（ego-browser，Profile 2）验证：
   - 侧栏「全局面板」出现第三个按钮 **墨戏画布**（与 插件 / 自动化任务 并列）✅
   - 点击后中央主面板渲染「墨戏生花 · 无限画布」✅
   - 面板内 `fetch('/api/moxi/hello')` 返回 Host 数据：`{plugin, version:'0.1.0-spike', pid:82423, cwd:'<仓库根>', time}` ✅
   - 截图：`/tmp/moxi-spike-canvas2.png`

### 5.2 踩到的坑（已解决）

| 坑 | 现象 | 修复 |
|---|---|---|
| `dsh --profile moxi web --port` | `error: too many arguments. Expected 0 arguments but got 1: web` | profile 自带的 bundle 决定界面形态：直接 `dsh --profile moxi --no-open --port N`，**不要**再加 `web` |
| 面板用 `position:absolute; inset:0` | 面板盖到侧栏上（截图 1） | 去掉 absolute，改 `height:100%; width:100%; overflow:auto`（截图 2 正常） |
| 根目录 curl 401 | 页面必须带 token URL 首次访问 | 从启动日志取 `?token=` URL |

### 5.3 结论与对 ADR 的输入

- **架构可行，无阻塞**。画布与后台都可以按 "Host 路由 + Client slot" 实现。
- **专用 profile 方案成立**：`moxi` profile 与 `desktop` 完全隔离，开发期不污染用户当前界面。
- **热更新方式**：改 `client.js` 后刷新页面即可（无需重启）；改 `index.js`（Host 半）需重启实例。
- **数据根**：Host CWD 由启动目录决定 → ADR 必须显式定义项目根路径（profile Config 或工具参数），不能依赖 CWD。
- **端到端旅程（S3 门）** 的三段已各自被证明：入口注册、面板渲染、Host 数据。剩下的是把它们做成画布。
