## 1. 背景与约束

旧系统：FastAPI + Vue3 Web 单体，45 个 router / 127 service / 32 model 文件（86 张表）/ 13 个页面视图，
103,346 行 Python、141 个 Vue 文件；648 个测试全绿（基线实测）。

**必须遵守的硬约束**：

1. 底座不换：DSH 是唯一 Agent 运行时，不引入第二个服务端框架。
2. 不替换 app root：客户端只往既有 slot 注入，不 fork 桌面壳。
3. 前端单框架：只 React。
4. 不引入第二个数据库服务：工作区文件 + DSH storage。
5. 脚本先于模型：确定性判断写脚本。
6. 删除要证据、每步可逆、每阶段过门。
7. 不把候选画布当成品。

**环境事实（实测）**：

- DSH `0.2.1-rc.5`；Web 客户端是 React + Slot；客户端产物 = `window.__ModuleLoader__.load({id, factory})`。
- Host 插件可用 `ctx.connection.fetch.register()` 注册 `/api/<ns>/*` 同源路由（仅 GET/HEAD/POST）。
- 侧栏入口 = `sidebar.panellist`（list），主面板 = `main`（keyed，key 与侧栏 id 同值）。
- 本机 Node v25.8.2 / pnpm 11.22.0 / Python 3.14.2（另有 3.11/3.12）；网络可达 GitHub 与 npm。

## 2. 决策（五平面落地）

```
┌───────────────────────────────────────────────────────────────┐
│ DSH 底座（会话 / Agent / 工具 / 技能 / 存储 / 审批 / Web UI）   │
│   profile: moxi（独立于 desktop）                              │
├──────────────────────┬────────────────────────────────────────┤
│ moxi-core (Host)     │ moxi-canvas (Client)  │ moxi-admin (Client)│
│ 业务唯一入口          │ 无限画布工作台         │ 管理后台 5 页       │
│ 服务 + 工具 + 路由    │ 侧栏 id: moxi-canvas  │ 侧栏 id: moxi-admin│
├──────────────────────┴────────────────────────────────────────┤
│ 领域内核：rules/ v2 · skills/ · scripts/（确定性检查/迁移/导出） │
├───────────────────────────────────────────────────────────────┤
│ 数据：项目工作区文件（JSON/MD/JSONL）+ DSH storage（索引/偏好）  │
└───────────────────────────────────────────────────────────────┘
```

### 2.1 三个 bundle 的边界

| bundle | 形态 | 职责 | **不负责** |
|---|---|---|---|
| `moxi-core` | Host 插件（无 client 半） | 项目/节点/连线的**唯一读写入口**；状态机；审计事件；确定性检查调用；导出；admin 聚合查询 | 不渲染 UI、不直接调模型 |
| `moxi-canvas` | Host 半（薄，仅 `/api/moxi/canvas/*` 路由转发）+ Client 半（画布 UI） | 画布交互、节点渲染、连线、撤销重做、与 core 通信 | 不自己写文件（必须走 core service） |
| `moxi-admin` | Host 半（薄）+ Client 半（5 页） | KPI/项目/规则技能/模型用量/日志导入导出 | 不做 SaaS/计费/多租户 |

> **为什么 canvas/admin 也有 Host 半**：DSH 的 Client 无法直接读文件，必须经同源 HTTP 路由；
> 路由归属哪个包决定部署粒度。把"路由转发"放在各自 bundle 的 Host 半里，
> 它们只依赖 `moxi-core` 服务，不复制业务逻辑。

### 2.2 端口/适配器纪律

- Client 只依赖 **DTO**（`/api/moxi/*` 的 JSON），不 import Host 代码。
- 旧 FastAPI 只经**一次性 ACL 迁移脚本**进入 v2，运行期零引用。
- 业务规则（阈值/口径）在 `rules/` 与 `scripts/`，**不写死在插件代码里**。

## 3. 数据契约（编译期锁定）

### 3.1 项目根

Host 插件 `Config.projectsRoot`，默认 `~/Documents/Moxi/projects`。**不依赖进程 CWD**（spike 证明 CWD 随启动目录变）。

### 3.2 单项目工作区

```
<projectsRoot>/<projectId>/
├── project.json          # 项目元数据（schema v1）
├── canvas.json           # 图：nodes[] + edges[] + viewport + rev
├── content/<nodeId>.md   # 节点正文（Markdown；剧本/大纲/设定）
├── assets/               # 角色/场景/道具附件（图片/JSON）
├── history/events.jsonl  # 追加式审计事件流（唯一变更日志）
├── versions/<nodeId>/    # 显式版本快照（内容不可变）
└── exports/              # 导出产物（docx/txt/md）
```

### 3.3 节点模型（9 类 IR）

每个节点固定五要素：**入边 / 内容 / 状态 / 历史 / 动作**。

```jsonc
{
  "id": "n_<ulid>",
  "type": "project_root|settings|asset|beat_sheet|scene_list|script_scene|quality|compliance|delivery",
  "title": "第 01 集 · 节拍",
  "status": "draft|generating|review|rejected|approved|blocked",
  "x": 0, "y": 0, "w": 320, "h": 200,
  "ref": { "episode": 1, "scene": null },   // 业务引用
  "contentFile": "content/n_xxx.md",
  "meta": {},                                // 类型特有字段
  "version": 3,
  "updatedAt": "2026-11-06T01:40:00+08:00"
}
```

### 3.4 状态机（不可跳步）

```
draft ──generate──▶ generating ──done──▶ review ──approve──▶ approved
  ▲                    │                    │
  └──────retry─────────┘                    └──reject──▶ rejected ──revise──▶ draft
```

- 质检/合规节点 `rejected` 时，其下游节点强制 `blocked`，**不允许绕过**。
- 合法迁移表写在 `moxi-core` 的 `TRANSITIONS` 常量里，非法迁移返回 `E_TRANSITION`。
- 每次迁移写一条 `history/events.jsonl`。

### 3.5 边

```jsonc
{ "id": "e_<ulid>", "from": "n_a", "to": "n_b", "kind": "context" }  // context | dependency
```

`dependency` 参与阻塞传播；`context` 只表示内容引用关系。

### 3.6 审计事件（history/events.jsonl）

一行一事件，**追加不改写**：

```jsonc
{ "seq": 12, "ts": "...", "actor": "user|agent|system", "op": "node.create|node.update|node.transition|content.save|edge.create|check.run|export", "projectId": "...", "nodeId": "...", "data": { ... }, "idempotencyKey": "..." }
```

`canvas.json.rev` 每次变更 +1；UI 用它判断是否需要重拉（轮询降载）。

## 4. Host API 契约（v1，全部 POST，路径 `/api/moxi/...`）

> DSH 的 connection 只允许 GET/HEAD/POST；统一用 POST + JSON body，便于幂等与审计。

| 路由 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `/api/moxi/hello` | `{}` | `{ok, value:{plugin,version,pid,cwd,projectsRoot}}` | 探活 + 自检 |
| `/api/moxi/projects/list` | `{}` | `{projects:[ProjectSummary]}` | 项目列表 |
| `/api/moxi/projects/create` | `{title,genre?,episodeCount?,logline?}` | `{projectId}` | 建项目（铺骨架节点） |
| `/api/moxi/project/get` | `{projectId}` | `{project, canvas, rev}` | 打开项目 |
| `/api/moxi/canvas/rev` | `{projectId}` | `{rev, updatedAt}` | 轮询轻量端点 |
| `/api/moxi/canvas/get` | `{projectId}` | `{canvas, rev}` | 拉全量图 |
| `/api/moxi/canvas/apply` | `{projectId, ops:[CanvasOp], idempotencyKey}` | `{rev, results}` | 批量原子操作（UI 写入口） |
| `/api/moxi/node/content` | `{projectId, nodeId}` | `{text, version}` | 读正文 |
| `/api/moxi/node/save` | `{projectId, nodeId, text, baseVersion}` | `{version}` | 保存正文（乐观锁） |
| `/api/moxi/check/run` | `{projectId, nodeId?}` | `{findings:[Finding], summary}` | 确定性检查 |
| `/api/moxi/export` | `{projectId, format}` | `{path, bytes}` | 导出 |
| `/api/moxi/admin/overview` | `{}` | KPI 聚合 | 后台工作台页 |
| `/api/moxi/admin/projects` | `{}` | 项目表 | 后台项目页 |
| `/api/moxi/admin/rules` | `{}` | 规则包/技能清单 | 后台规则页 |
| `/api/moxi/admin/models` | `{}` | 模型与用量（读 DSH 配置 + 探针） | 后台模型页 |
| `/api/moxi/admin/logs` | `{limit, cursor}` | 审计/日志页 | 后台日志页 |

**CanvasOp**（原子操作集）：

```jsonc
{ "op": "node.create", "node": {type,title,x,y,meta} }
{ "op": "node.update", "nodeId": "...", "patch": {x,y,w,h,title,meta} }
{ "op": "node.transition", "nodeId": "...", "to": "review", "reason": "..." }
{ "op": "edge.create", "from": "...", "to": "...", "kind": "dependency" }
{ "op": "edge.delete", "edgeId": "..." }
{ "op": "node.delete", "nodeId": "..." }
```

## 5. Agent 工具契约（Host 工具，供对话驱动）

| 工具 | 作用 |
|---|---|
| `moxi_project_create` | 建项目 |
| `moxi_project_open` | 打开项目，返回画布摘要 |
| `moxi_node_create` | 建节点（可指向父节点自动连线） |
| `moxi_node_update` | 改标题/位置/meta |
| `moxi_node_write` | 写节点正文（Markdown） |
| `moxi_node_transition` | 状态迁移（走状态机） |
| `moxi_edge_create` | 连线 |
| `moxi_check_run` | 跑确定性检查，返回 findings |
| `moxi_export` | 导出 |

> 工具与 HTTP 路由**共用同一个 service 层**（`moxi-core`），保证"唯一业务入口"。
> 所有写工具带 `idempotencyKey`（默认由 op+nodeId+内容 hash 生成）。

## 7. 失败、降级、回滚

| 场景 | 处置 |
|---|---|
| Host 路由抛错 | 统一 `{ok:false, error:{code, message}}`；Client 显示错误态，不白屏 |
| 写文件失败 | 先写临时文件再 rename（原子）；失败回滚内存 rev |
| 状态机非法迁移 | 返回 `E_TRANSITION`，附 allowed 集合 |
| 正文并发写 | `baseVersion` 乐观锁；不匹配返回 `E_CONFLICT` 并回传最新文本 |
| 迁移校验不为 0 | 停机，旧库只读，修脚本，不进下一批 |
| 插件装不上 | 逐条排查 package/patch/slot；不绕过 G1 |
| 回滚 | 每阶段 git tag；`archive/` 旧码只读；数据目录 git 化（可选） |

## 8. 取舍（为什么不是别的做法）

1. **为什么不复用旧 FastAPI 做后端**：它不是 DSH 运行时；保留它 = 第二套 Agent 调度/会话/工具，违反硬约束 1 与"唯一业务入口"。
2. **为什么不把画布做成独立窗口/iframe**：iframe 拿不到主题 token 与 locale（`references/practices.md` 明文）；独立窗口要 fork 桌面壳（硬约束 2）。
3. **为什么不用 SQLite**：硬约束 4；且项目数据要可 diff / 可 git / 可人读。
4. **为什么自研画布而不 fork NINKCH**：NINKCH 领域耦合深（生图/生视频/成片），改皮成本 > 自研最小内核；且许可与体积（23.1MB 解包）都更重。仍会借它的节点交互与数据结构。
5. **为什么用轮询而不是 push**：DSH 会话事件不承载项目文件状态；`connection` 只给 HTTP 路由。1.5s 轮询一个 `rev` 端点的成本可忽略，换来零耦合与可调试。
