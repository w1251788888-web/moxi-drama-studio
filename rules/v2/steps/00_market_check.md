## 市场可行性检查（Gate — 概念规划前强制执行）

本步骤是**硬性门控**：不通过则不进入 concept 创作环节。
目的：在投入大量创作资源前，用最低成本验证项目是否有商业立项价值。

---

项目类型：${project_type}
受众轴：${audience_axis}
主类型：${genre_main}
副类型：${genre_sub}
集数：${episode_count}
创作简介（brief）：${brief}

近期市场信号（RAG 检索热榜/评论/DataEye，作为判断证据）：
${rag_market_signals}

---

## 四项二元检查

逐项判断，每项只填"通过"或"未通过"，同时给出1-2句判断依据。

### 检查1：题材热度
- **通过标准**：该题材/设定组合在目标受众轴的平台（抖音/快手/红果）当前 TOP10 热榜中有同类内容

### 检查2：对标验证
- **通过标准**：能举出 2 部以上同类型成功先例（播放量过亿 或 付费率高于平台均值）

### 检查3：差异化
- **通过标准**：本项目与对标作品有 1 处以上可见差异（新设定 / 新视角 / 新人物关系 / 新情绪爆点）；不能只是换主角名字

### 检查4：话题传播力
- **通过标准**：初步构想中已有 2 个以上"可截图传播"的场面或金句设计（不需要已写出，有清晰设想即可）

---

## 门控结论规则

| 通过项数 | 结论 | 处理 |
|---------|------|------|
| 4/4 | 强推荐立项 | 直接进入 concept |
| 3/4 | 推荐立项 | 进入 concept，附加优化建议 |
| 2/4 | 风险立项 | **软阻断**：返回警告，人工确认是否继续 |
| 1/4 及以下 | 不推荐立项 | **硬阻断**：拒绝进入 concept，必须修改 brief 后重新执行本步骤 |

---

## 输出要求（严格）

只输出一个 JSON 对象，字段：`market_check_result`

```json
{
  "market_check_result": {
    "checks": {
      "topic_heat": {
        "result": "通过 / 未通过",
        "reason": "判断依据1-2句"
      },
      "benchmark_validation": {
        "result": "通过 / 未通过",
        "reason": "举出具体对标作品名称（若通过）或说明缺失原因",
        "examples": ["作品A", "作品B"]
      },
      "differentiation": {
        "result": "通过 / 未通过",
        "reason": "差异化点描述"
      },
      "topic_virality": {
        "result": "通过 / 未通过",
        "reason": "预设传播点描述（若通过）"
      }
    },
    "passed_count": 0,
    "verdict": "pass / warn / reject",
    "verdict_reason": "综合判断说明（1-2句）",
    "optimization_suggestions": [
      "若 verdict=warn/reject：给出1-3条可提升通过率的具体建议"
    ]
  }
}
```

**verdict 映射：**
- `pass`：≥3项通过 → 前端允许进入下一步
- `warn`：2项通过 → 前端显示警告弹窗，人工点击"确认风险继续"后方可进入
- `reject`：≤1项通过 → 前端硬阻断，不允许进入 concept，显示优化建议
